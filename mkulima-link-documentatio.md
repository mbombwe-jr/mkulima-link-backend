# Mkulima Link Backend Documentation

**Version:** 1.0.0  
**Backend:** NestJS 11, TypeScript, Prisma, PostgreSQL 15, Redis 7  
**Pilot region:** Dodoma, Tanzania  
**Currency:** Tanzanian Shilling (TZS)

## Overview

Mkulima Link is a B2B crop marketplace connecting approved buyers with smallholder sellers. The platform fixes crop prices, matches sellers to buyer demands, locks buyer funds in escrow, and pays sellers after delivery confirmation while retaining a configurable commission.

This repository contains the production API. Interactive OpenAPI documentation is generated by NestJS Swagger at:

- Swagger UI: `http://localhost:3111/docs`
- OpenAPI JSON: `http://localhost:3111/docs-json`
- Health: `http://localhost:3111/health`

## Architecture

| Layer | Implementation |
|---|---|
| HTTP API | NestJS REST controllers and validated DTOs |
| API docs | `@nestjs/swagger` with compile-time DTO metadata |
| Database | PostgreSQL 15 through Prisma ORM |
| Sessions | Redis for OTP, refresh tokens, and USSD sessions |
| Authentication | Phone OTP/JWT for users; password, optional TOTP, and JWT for admins |
| Authorization | Global JWT guard and role-based access guard |
| Payments | Real ClickPesa collection/disbursement HTTP client and signed webhook |
| SMS | Real Beem Africa SMS HTTP client and delivery callback |
| USSD | Beem-compatible `CON`/`END` state flow |
| Jobs | NestJS Scheduler for expiry and auto-confirmation |
| Tests | Jest unit tests, Supertest HTTP tests, PostgreSQL integration workflow |
| Deployment | Docker multi-stage image and Docker Compose |

## Local Setup

Requirements: Node.js 22+, npm, Docker, and Docker Compose.

```bash
cp .env.example .env
npm install
docker compose up -d postgres redis
npm run prisma:deploy
npm run prisma:seed
npm run start:dev
```

The API listens on port `3111` by default.

The seed creates platform defaults, the singleton platform wallet, and the initial 5% commission. It creates an administrator only when `DEFAULT_ADMIN_PASSWORD` is set. Change the seeded password immediately outside local development.

## Authentication

### Mobile users

1. Call `POST /auth/request-otp` with `phone` and `role`.
2. Call `POST /auth/verify-otp` with the six-digit OTP.
3. A new phone receives a short-lived `registration` token used once with `/sellers/register` or `/buyers/register`.
4. An existing phone receives an access token and a Redis-backed refresh token.
5. Send the access token as `Authorization: Bearer <token>`.

OTP rules:

- E.164 Tanzanian phone format: `+255XXXXXXXXX`
- Six digits, valid for five minutes
- Three requests per phone per hour
- Three verification attempts before lockout

Access JWT claims include `sub`, `role`, `isVerified`, `isDisqualified`, and optional `phone`. Refresh tokens are revocable and are removed by logout.

### Administrators

`POST /admin/auth/login` accepts email, password, and `totp` when the account has a TOTP secret. Admin roles are `super_admin` and `helpdesk`. Helpdesk access is read-only except for support ticket management.

## Core Rules

- Sellers are approved immediately; buyers require Super Admin approval.
- Only active prices set by the platform can be used.
- A demand locks the current crop price when created.
- A delivery deadline must be at least three days away.
- Sellers see matching crops in their region and cannot commit twice.
- A PostgreSQL row lock serializes simultaneous commitments to the same demand.
- Order commitment atomically decreases available buyer balance and increases locked escrow.
- Commission is locked into the order at commitment and defaults to 5%.
- Delivery confirmation atomically consumes escrow, credits the seller, and credits the platform.
- ClickPesa references are unique; duplicate callbacks return successfully without another mutation.
- Wallet and quantity database checks prevent negative balances and over-fulfilment.
- Delivered orders auto-confirm after 24 hours.
- Expired commitments unlock escrow and reopen their demand quantity.
- Seller ratings below the configured threshold disqualify the seller after the configured minimum count.

All routes require Bearer authentication unless marked public. Request and response schemas are available in Swagger.

| POST | `/auth/change-pin` | Seller |
| POST | `/admin/auth/login` | Public |

| GET, PUT | `/buyers/me` | Buyer |

### Prices and demands

| Method | Route | Access |
|---|---|---|
| GET | `/prices` | Authenticated |
| GET | `/prices/:cropId` | Authenticated |
| GET | `/prices/:cropId/history` | Admin/helpdesk |

List routes accept `page` and `limit` (maximum 100). Demand lists also accept `cropId`, `region`, and `status` as applicable.

### Orders

| Method | Route | Access |
|---|---|---|
| POST | `/orders` | Seller |
| GET | `/orders/mine` | Buyer/seller |
| GET | `/orders/:id` | Participant/admin |
| POST | `/orders/:id/delivered` | Owning seller |
| POST | `/orders/:id/confirm` | Owning buyer |

Commit body:

```json
{ "demandId": "uuid", "quantityKg": 100 }
```

Delivery supports optional `deliveryNotes` and `deliveryPhotoUrl`. Clients should upload media to approved object storage and submit its HTTPS URL.

### Wallet and ratings

| Method | Route | Access |
|---|---|---|
| GET | `/wallet/me` | Buyer/seller |

| POST | `/wallet/withdraw` | Seller |
| POST | `/ratings` | Buyer after settlement |

Top-up and withdrawal accept `amount`, optional `provider`, and optional E.164 `phone`. Providers are `MPESA`, `TIGO_PESA`, `AIRTEL_MONEY`, and `HALOPESA`.

### Support, USSD, and webhooks

| Method | Route | Access |
|---|---|---|
| POST | `/support/tickets` | Buyer/seller |
| GET | `/support/tickets/mine` | Buyer/seller |
| GET, PUT | `/admin/support/tickets[/:id]` | Admin/helpdesk |
| POST | `/ussd/callback` | Public; `X-Beem-Token` when configured |
| POST | `/webhooks/clickpesa` | Public; signed |
| POST | `/webhooks/beem/delivery` | Public |

The USSD callback accepts `sessionId`, `phoneNumber`, accumulated `text`, and `serviceCode`, and responds as `text/plain` beginning with `CON` or `END`.

ClickPesa callbacks require `X-ClickPesa-Signature`, the lowercase hexadecimal HMAC-SHA256 of the unmodified request body. The payload is:

```json
{ "reference": "TOPUP-uuid", "status": "SUCCESS", "amount": 50000 }
```

## Error Format

All application and validation errors use one envelope:

```json
{
  "error": {
    "code": "REQUEST_FAILED",
    "message": "Only 100kg remains",
    "detail": null,
    "path": "/orders",
    "timestamp": "2026-09-09T10:30:00.000Z"
  }
}
```

Typical statuses are 400 for validation, 401 for missing/invalid JWT or webhook signature, 403 for role/account restrictions, 404 for missing resources, 409 for invalid lifecycle transitions, 422 for business validation, 429 for rate limits, and 503 for unavailable payment infrastructure.

## Scheduled Jobs

| Schedule | Operation |
|---|---|
| Every 10 minutes | Expire overdue committed orders and release escrow |
| Every hour | Confirm deliveries older than 24 hours and settle payment |
| Daily at 01:00 | Expire overdue unfulfilled demands and release commitments |

Jobs use the same transaction-safe service methods as HTTP requests and are safe to rerun.

## Database

Prisma models cover users and profiles, admins, crops and regional price history, delivery windows, demands, orders, wallets and immutable ledger entries, platform commission, ratings, seller notifications, SMS logs, audit logs, tickets, commission history, and platform settings.

Deploy migrations with:

```bash
npm run prisma:deploy
```

Create a development migration after changing `prisma/schema.prisma`:

```bash
npm run prisma:migrate
```

Never use `prisma migrate reset` against staging or production.

## Testing

```bash
npm test
npm run test:e2e
npm run lint
npm run build
```

The database integration suite needs an empty PostgreSQL test database in `DATABASE_URL`. It verifies demand creation, commitment, escrow, delivery, settlement, platform commission, seller payout, and rating. External Beem and ClickPesa calls are disabled or mocked in tests.

For an isolated local test database:

```bash

DATABASE_URL=postgresql://test:test@localhost:55432/mkulima_test npm run prisma:deploy
DATABASE_URL=postgresql://test:test@localhost:55432/mkulima_test npm run test:e2e
```

## Production Checklist

- Set RS256 keys, strong provider secrets, and `OTP_EXPOSE_IN_RESPONSE=false`.
- Restrict Swagger to internal networks if API schemas are sensitive.
- Configure HTTPS at the ingress and trusted CORS origins.
- Register the public ClickPesa and Beem callback URLs.
- Restrict USSD callbacks by token and provider IP ranges at the ingress.
- Run `npm run prisma:deploy` before replacing API containers.
- Run at least two API replicas; scheduled jobs should run in one designated process.
- Back up PostgreSQL with daily snapshots and point-in-time recovery.
- Alert on payment callback failures, failed SMS, job failures, and health checks.
- Forward structured application and audit logs to the monitoring platform.
